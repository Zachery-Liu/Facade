# Facade v0.1 修订实施计划

> 状态：实施基线  
> 关联需求：[Facade 产品规划](./facade_product_plan.md)  
> 修订日期：2026-09-06

## 1. 目标、范围与交付状态

实现以下静态分发链路：

```text
GitHub Release + 项目配置
            ↓
     归一化公开 Manifest
            ↓
HTML + manifest.json + install.md + llms.txt
            ↓
       GitHub Pages
```

本计划替代之前的实施拆解，并修正条件判断、推荐、验证材料和部署并发的承诺。技术栈为 TypeScript、pnpm、Zod、Octokit、commander、Preact、Vite、Vitest 和 Playwright；只维护一个主软件包与一个 Action 入口。

v0.1 包含 Product Theme、`init` / `inspect` / `build`、三个静态 Agent 接口、GitHub 数据源及两种发布接入方式。第二主题、dev server、Playground、自动安装、MCP、Agent Server 和实际签名验证均后移。

| 状态 | 完成标准 |
|---|---|
| 本地实现完成 | 代码、打包、离线及浏览器测试通过 |
| 发布候选就绪 | 产物冒烟检查、协议文档及接入模板完成 |
| 外部验收完成 | 真实 Pages、三个仓库和独立用户接入已验证 |
| 正式发布完成 | 身份、许可证、发布授权和发布后检查完成 |

缺少远端仓库、权限或体验者不阻塞本地开发，但对应验收必须保持待完成。

## 2. 实施前冻结的产品行为

### 2.1 条件、环境与缺失信息

每项已声明的兼容条件只产生 `match`、`mismatch` 或 `unknown`：环境满足是 match；明确不满足是 mismatch；环境缺失或无法比较是 unknown。

项目未声明的限制不生成条件，改写入 `missingMetadata`；当前平台不适用的条件不参与匹配。`libc: none` 是作者明确声明的 Linux 事实，不能与 unknown 或不适用混用。

最终选择结果同时返回“已声明条件的匹配结果”和“未获得的兼容信息”。缺少最低系统版本不会阻止展示或推荐，但界面只能称“符合已提供条件”，不能称完全兼容。

OS 或架构未知时不能得出具体平台首选。macOS Universal 只表示其明确声明支持的 macOS 架构集合，不表示跨任意 CPU 或系统通用。

最低版本仅接受点分非负整数，按数字段比较，尾部缺段补零。不支持名称、范围或任意 SemVer。无法规范化环境版本时返回 unknown。Linux 系统版本没有发行版模型前不参与自动比较，应优先使用 glibc / musl 要求。

### 2.2 共享选择器

Manifest 保留文件、条件和候选索引，但不生成按 OS / arch 的无条件 `preferredId`。新增唯一选择入口：

```ts
selectInstallation(manifest, environment, policy): SelectionResult
```

浏览器和只读 Agent 示例共用这个纯函数。结果包含 `selected`、`needs-input` 或 `no-match`，每个候选的排序理由、条件结果及 `missingMetadata`；仅有唯一首选时返回 selected。

选择器先排除明确不兼容候选，再按作者 priority、精确架构匹配和文件用途排序。同分保留选择；文件名只用于稳定显示排序。Linux 多格式在没有作者格式偏好时保留选择；已声明 libc 但环境 libc 未知时返回 needs-input。

默认策略允许文件名规则推断参与只读推荐，并保留 evidence。严格消费者可要求字段仅来自项目声明或 GitHub API，未满足时返回 needs-input。无论哪种策略，结果均不构成安装授权。

### 2.3 安装偏好及回退

按配置顺序评估 installationPreferences：

1. `when` 明确不匹配时继续下一条。
2. `when` 未知时返回 needs-input，不跳过高优先级规则。
3. 首条明确匹配规则按 `prefer` 顺序评估。
4. 当前候选明确不适用时继续当前列表；候选条件未知时返回 needs-input。
5. 当前列表为空或全部不适用时，进入默认 Artifact 选择，不再匹配后续偏好规则。
6. 没有匹配规则时，直接使用默认 Artifact 选择。

`assetMatch` 零匹配产生警告并移除该项；多匹配保留候选。不存在 method ID 是配置错误。包管理器命令默认 `unverified`；校验失败不是回退条件，安装说明要求消费者停止，Facade 不执行命令或验证。

### 2.4 验证材料

用 `verificationMaterials` 替代固定状态：可声明签名文件引用、GitHub Attestation 的预期仓库及 source commit。Facade 只验证引用结构，不验证签名或证明，不输出 `verified` 字段或可信徽章。GitHub API 提供的摘要独立保存并保留来源。

带 sourceCommit 的规则必须精确限定 tag；当前 tag 不匹配则整个规则不应用并给出诊断。签名引用必须唯一指向当前 Release 中未排除的 signature Asset。

### 2.5 两层校验和部署承诺

JSON Schema 负责类型、必填项、格式和枚举；共享语义校验负责 ID 唯一、引用完整性、evidence 路径、签名用途、渠道冲突及跨字段条件。构建必须通过两层，消费者也必须检查协议版本与必要语义。缺失字段通过 `missingMetadata` 表达，不生成指向不存在字段的 evidence。

v0.1 保证串行部署、完整产物、构建失败不替换线上站点；不承诺并发变更时绝不会短暂展示旧内容。部署阶段重新读取配置和 Release，发现输入变化时重建一次；持续变化则失败并提示重跑。所有静态 Artifact 下载链接直连 GitHub；外部包管理器的来源不在此承诺范围内。

## 3. 按依赖推进的任务包

### T00 — 同步产品规划

修订关联产品规划的配置示例、Manifest、推荐和验收条目，删除旧 `preferredId`、固定 verification status、混用 unknown 和过强并发保证；建立本文件的任务状态与外部依赖记录。

**完成条件：** 计划与本节行为完全一致。

### T01 — 工程与打包骨架

初始化 workspace、严格 TypeScript、CLI 和内部模块；建立 typecheck、test、build、CI、Node 支持范围与不可误发布的开发配置。

**完成条件：** 干净安装通过检查；打包后的 CLI `--help` 不依赖源码运行。

### T02 — Fixtures、结构 Schema 与语义校验

采集五类公开仓库快照，记录来源和 tag；标注分类、推荐、未知信息和辅助文件；实现配置、Source、Manifest 的 Schema，建立语义校验及失败样例。

**完成条件：** 普通测试完全离线，样本有可解释预期，协议尚未冻结。

### T03 — 最小离线闭环

首批样本只支持明确 token 的 macOS ARM64 DMG、Windows x64 EXE、Linux x64 归档与 checksum 文件。实现 fixture 输入、基础分类和编译，输出基础 HTML、manifest.json、install.md、llms.txt；实现 basePath、保留路径和原子产物替换。

**完成条件：** 四种输出共享版本、Asset ID 和下载 URL；根路径及项目子路径可用；无 JavaScript 时仍可下载；任一输出失败不替换旧产物。

### T04 — GitHub Source

实现 Latest、指定 tag、仓库信息及 Assets 分页；统一 CLI、配置和环境的参数优先级；加入有限重试、错误分类和来源记录；只使用 API 提供的摘要。

**完成条件：** 三类真实仓库可构建；分页、draft、无 Latest、认证及网络失败有测试；日志和产物没有令牌或绝对本地路径。

### T05a — Action 与工作流工程接入

实现调用共享构建入口的 Action，以及手动 Release 和现有 CI 串联模板；实现完整附件上传后的构建、串行部署和输入新鲜度检查。未公开发布时，模板使用测试仓库可访问的固定 commit，而不是虚构的 Action 版本。

**完成条件：** Action 打包和工作流模板校验通过，可继续本地开发。

### T05b — 真实 Pages 验证

在可用测试仓库上验证两种发布入口、项目子路径、完整产物、构建失败恢复及并发刷新，并记录运行证据。此任务不阻塞 T06 至 T10。

**完成条件：** 真实行为符合第 2.5 节；无外部资源时保持待验收。

### T06 — 完整分类、覆盖与 inspect

完成 OS、arch、format、kind、libc、冲突及 token 边界；实现顺序覆盖、排除、priority、tag 限定和规则诊断；记录字段来源与覆盖轨迹；实现 inspect 文本与 JSON。

**完成条件：** 辅助文件不进入推荐；冲突保留明确诊断；覆盖可解释；inspect 与 build 一致。

### T07 — 共享条件选择器

实现条件匹配、缺失信息、候选排序、安装偏好回退、环境输入和来源策略；覆盖 Universal、glibc / musl、命令可用性和未绑定版本。

**完成条件：** 未知环境不默认 x64 或 glibc；未声明最低版本不让全部文件失去推荐；浏览器与只读消费者得到一致结果。

### T08 — 完整 Agent Interface

完成 evidence、channel、verificationMaterials 与引用校验；完善 install.md、llms.txt、JSON Schema、有效和无效样例；提供只选择、不下载、不安装的消费者示例。

**完成条件：** 结构与语义校验均通过；未知协议安全退出；不产生错误验证声明；自由文本不改变结构化条件。

### T09 — 正式 Product Theme

完成产品信息、品牌素材、条件标签、安装命令和更新说明；集成共享选择器和手动选择；实现浅色、深色、自动外观、强调色、复制反馈、响应式、键盘操作及 Markdown 安全处理。

**完成条件：** 无 JS、多候选、未知架构、无图片和长文本场景可用；人机输出一致；无虚假兼容或验证承诺。

### T10 — init 与使用体验

实现不覆盖既有文件的 init，生成两类接入模板，完成 CLI 帮助、错误码、构建摘要、Pages 初次设置、配置、故障排查和升级文档；执行打包安装冒烟检查。

**完成条件：** 从打包产物可完成 init、inspect、build，不需要 Facade 开发依赖。

### T11a — 本地发布候选验收

执行类型、单元、Source、契约、集成及浏览器检查；使用留出样本验证；检查确定性、路径安全、Markdown、完整产物替换；生成候选产物与待办报告。

**完成条件：** 标记“发布候选就绪”，但不标记正式发布。

### T11b — 外部验收

依赖 T05b、T11a 和外部体验者。验证至少三个真实仓库，安排至少一位非核心开发者按文档独立接入，修复阻断项后复验。

**完成条件：** 证据齐全，无未修复接入阻断项。

### T12 — 协议冻结与正式发布

冻结 schemaVersion 1 和兼容规则；确认许可证、包名、Action 地址和发布授权；将候选升级为正式版本，发布版本化文档并完成发布后验证。

**完成条件：** 发布物与最终验收一致，无占位地址，公开接口可消费。

## 4. 测试与验收矩阵

| 领域 | 必测场景 |
|---|---|
| 条件语义 | 未声明、环境未知、不适用、明确无依赖 |
| 版本条件 | 点分比较、尾部零、无效格式、环境无法规范化 |
| 推荐 | glibc / musl 同架构、并列候选、未知架构、Universal |
| 安装偏好 | when 未知、首选不可用、全不可用、零匹配、错误方法引用 |
| 来源策略 | API、作者声明、规则推断、派生值、严格策略 |
| 验证材料 | tag 失配、签名歧义、缺少材料、不输出 verified |
| 契约 | Schema 通过但语义失败、重复 ID、悬空引用、无效 evidence |
| 人机输出 | 相同版本和文件、相同选择、子路径、Markdown 转义 |
| 页面 | 无 JS、键盘、移动端、复制失败、长文本、无品牌素材 |
| 构建部署 | 输出失败、旧产物保留、串行部署、输入变化后重建 |
| 打包 | 干净安装、CLI 可执行、Action 无源码开发依赖 |
| 外部验收 | 两种发布入口、三个仓库、独立用户接入 |

验收样本不允许出现错误平台、错误架构或辅助文件成为最终首选。识别不足必须保留选择和诊断，不得靠猜测提高覆盖率。

## 5. 执行约定

- 每个任务包记录交付物、验证命令、结果和待办；测试随实现完成。
- 本地任务和外部验收分开跟踪；不伪造通过，也不因缺少远端权限阻塞无关工作。
- 三个静态 Agent 接口是 v0.1 必交付项；自动执行和实际验证不是。
- 协议发布前可以调整，正式冻结后依兼容规则演进。
- 安装偏好仅为作者声明，不替代消费者授权、来源信任或验证策略。
- 不承诺日历工期，以任务出口与实际证据衡量进展。
